## 2. 백엔드 규칙 (앱이 맞춘 것)

- 주소 앞부분 `/api/v1`, `Authorization: Bearer <accessToken>`. 액세스 30분 · 리프레시 30일(서버 기본값).
- 오류 응답은 평평한 객체:
  `{ "timestamp", "status", "code", "message", "path", "requestId", "fieldErrors": { "필드": "사유" } }`
  - 앱은 `code`로 문구를 고른다. 서버 `message`는 대부분 "요청을 처리할 수 없습니다."라 쓰지 않는다.
  - 공통 코드: `COMMON_001`(형식 오류) · `COMMON_002`(없음) · `AUTH_001`(토큰 없음 · 만료) · `AUTH_002`(권한 없음) · `TOO_MANY_REQUESTS` · `COMMON_500`
- ID는 숫자(Long) — 앱은 `Int64`. 업체 `placeId`만 문자열.
- 로그인 요청 `{ phoneNumber, password, deviceToken? }`, 응답 `{ user: { userId, role, name }, accessToken, refreshToken }`.
- 역할 `GUARDIAN · BUSINESS · OPERATOR`. 앱은 **GUARDIAN만** 받고, 다른 역할이면 토큰을 저장하지 않고 "보호자 계정으로 로그인해 주세요".
- 판정 값: `ENTRY_OK · PREPARE · CHECK_REQUIRED · ENTRY_DENIED` (기능 명세서의 UNKNOWN · NO_ENTRY 대신). 나쁜 순서 ENTRY_DENIED > CHECK_REQUIRED > PREPARE > ENTRY_OK는 우리 결정(빨강 > 회색 > 노랑 > 초록)과 같다.
- 휴대폰 번호는 010만 받는다(`^(?:\+82[- ]?|0)10[- ]?\d{4}[- ]?\d{4}$`).
- 시연 서버 휴대폰 인증번호 **123456 고정**.

## 2-1. 코드 대조 결과 (11-12, BE develop d6961cf)

로그인 흐름 전체를 서버 코드(AuthController · AuthService · TokenService · JwtAuthenticationFilter · SecurityConfig · MemberController)와 한 줄씩 맞춰 봤어요.

| 확인한 것 | 서버 | 앱 | 결과 |
| --- | --- | --- | --- |
| 로그인 요청 | `phoneNumber`(010만, 하이픈 허용) · `password` · `deviceToken?` | 숫자만 보냄, deviceToken 없음 | 맞음 |
| 로그인 응답 | `user{userId, role, name}`, `accessToken`, `refreshToken` | 같은 모양으로 디코딩 | 맞음 |
| 인증 헤더 | `Authorization: Bearer` | 같음 | 맞음 |
| 토큰 만료 | 필터가 인증을 비우고 401 `AUTH_001` | `AUTH_001`이면 갱신 후 1번 재요청 | 맞음 |
| 토큰 갱신 | **회전**: 새 리프레시 토큰을 주고 이전 것은 폐기 | 새 토큰 저장 | 맞음 (아래 고친 것 2) |
| 로그아웃 | **로그인 필요** + 액세스 토큰 주인 = 리프레시 토큰 주인 | 저장된 토큰으로 보냄 | 맞음 (아래 고친 것 1) |
| 내 정보 | `GET /users/me` → `phoneNumber`는 숫자만 저장 | 화면에서 하이픈 붙여 표시 | 맞음 |
| 오류 응답 | `{status, code, message, path, requestId?, fieldErrors}` | `code`로 문구 선택 | 맞음 |
| null 처리 | `non_null` → **null 필드는 응답에서 빠짐** | Optional로 선언 | 맞음 — 앞으로 만들 모델도 꼭 Optional |
| 판정 값 | `ENTRY_OK · PREPARE · CHECK_REQUIRED · ENTRY_DENIED` | 같은 이름 | 맞음 |

고친 것 (Fix 커밋)

1. **보호자가 아닌 계정 로그인 시 로그아웃이 실패하던 문제** — 서버 로그아웃은 로그인이 필요한데, 저장하지 않은 토큰이라 헤더 없이 보내져 401 → 앱이 "세션 만료"로 처리했어요. 받은 액세스 토큰을 직접 실어 보내도록 고침(서버에 남는 토큰도 폐기됨).
2. **토큰 갱신 중 동시 요청** — 갱신을 기다리던 다른 요청이 새 토큰 저장 전에 재요청해 다시 401이 날 수 있었어요. 저장까지 갱신 작업 안에서 끝내도록 고침.
3. **연결 오류에도 로그아웃되던 문제** — Render 서버가 깨어나는 중(시간 초과)이나 5xx에도 토큰을 지웠어요. 서버가 토큰을 거절(4xx)했을 때만 로그아웃하도록 고침.

알아 둘 것

- 탈퇴 · 비활성 계정: 액세스 토큰은 거절되지만 리프레시 토큰 갱신은 서버에서 통과돼요(`findUsable`이 사용자 상태를 안 봄). 앱은 갱신 후 재요청이 다시 401이면 오류로 끝나서 무한 반복은 없어요. → 백엔드에 갱신 때도 사용자 상태 확인 요청.
- 시작 화면에서 서버 연결이 안 되면(오프라인 · 서버 기상 중) 로그인 화면으로 가요. 토큰은 남아 있어서 다시 로그인하면 돼요.
