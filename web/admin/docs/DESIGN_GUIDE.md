# PawFit 업체 · 운영자 웹 디자인 가이드

업체 센터(PawFit-partner-frontend)와 운영자 콘솔(PawFit-admin-frontend)이 같이 따르는 디자인 방향과 화면 규칙이에요.
두 프로젝트에 같은 문서가 있어요. 바꿀 때는 양쪽을 같이 고쳐 주세요.

---

## 1. 디자인 방향

### 색 · 분위기
- **업체 센터**: 흰 화면 + 파란색 `#2348C9` 기본.
- **운영자 콘솔**: 어두운 사이드바(`#15181D`) + 노란 숫자 배지(`#F5C451`).
- 두 화면이 한눈에 구분되도록 사이드바 색을 다르게 둬요.

### 글꼴 · 토큰
- 글꼴은 **IBM Plex Sans KR**.
- 색 · 글자 크기 · 간격 · 모서리 값은 `src/styles/tokens.css` 에서만 정해요. 화면에서는 `var(--color-primary)` 처럼 변수만 써요.
- 토큰 값은 Figma Components 와 같아요.

### 입장 판정 4단계
| 판정 | 색 |
| --- | --- |
| 입장 가능 | 초록 |
| 준비 필요 | 노랑 |
| 입장 불가 | 빨강 |
| 조건 확인 필요 | 회색 |

- **색만으로 구분하지 않아요.** 아이콘과 글자를 항상 함께 보여줘요 (QUR-001). → `JudgmentChip`

### 처리 상태 (서버 값: RECEIVED · IN_REVIEW · NEEDS_INFO · APPROVED · REJECTED · CANCELED · CLOSED_NOT_APPROVED)
| 상태 | 색 |
| --- | --- |
| 접수 | 회색 |
| 검토 중 | 파랑 |
| 승인 | 초록 |
| 반려 | 빨강 |
| 보완 요청 | 노랑 |
| 취소 | 흰 바탕 + 회색 테두리 |
| 모집 종료 · 미승인 | 흰 바탕 + 회색 테두리 (참여 신청 표시 전용) |

- 모든 화면에서 같은 칩을 써요. → `StatusChip`

### 사실만 말하기
숫자나 상태가 오해되지 않게 안내 문구를 붙여요.
- QR 통계: "PawFit QR 인증 기준 · 전체 방문객 수 아님"
- 미확인 조건: 회색 + "조건 확인 필요"
- 광고: "입장 판정 색은 광고와 관계없이 그대로예요"
- 확인되지 않은 조건을 '가능'이라고 안내하지 않아요.

### 신뢰 장치
- **조건 확인일**과 **QR 인증일**을 따로 관리해요. QR 인증일은 정책 최신성의 근거가 아니에요.
- 조건 확인일이 **30일**을 넘으면 노란색으로 표시하고 재확인을 요청해요.
- 입장 조건을 바꿀 때는 **근거 자료**(공지 캡처 · 링크)를 같이 받아요.

### 문체
- 짧은 해요체. 예: "보통 1–2일 걸려요.", "수정 요청을 보냈어요."
- 버튼은 동작을 그대로 적어요. 예: "수정 요청 보내기", "승인하기", "PNG 내려받기"

## 2. 화면 규칙

### 업체 센터
- **입장 조건 수정 요청**
  - 업체는 조건을 직접 바꿀 수 없어요. 운영자가 승인해야 반영돼요.
  - 근거 자료가 1개 이상 있어야 보낼 수 있어요.
  - 이미 검토 중인 항목은 다시 요청할 수 없어요.
  - 바뀐 항목은 테두리 + "변경됨" + `현재 → 바뀐 값` 으로 바로 보여줘요.
- **광고 신청**
  - 1주 단위, 월요일 시작.
  - 매장이 있는 지역에만 신청할 수 있어요.
  - 운영자 검토 전까지만 기간 수정 · 취소할 수 있어요.
- **이벤트 신청**
  - 참여 비용은 없어요.
  - 코스 소개 문구는 40자 이내.
  - 이벤트 지역에 있는 인증 완료 매장만 신청할 수 있어요.

### 운영자 콘솔
- **처리 결과**
  - 보완 요청 · 반려는 업체에 보낼 메모를 꼭 써야 해요.
  - 경계값이 겹치면 (예: 실내 '10kg 이하' / 테라스 '10kg 이상') 처리 결과를 '보완 요청'으로 먼저 골라 둬요.
  - 승인 · 반려된 요청은 대기열에서 빠지고 업체 처리 이력에 남아요. 보완 요청은 '보완 대기'로 남아요.
- **이벤트 신청 검토**: 코스 소개 문구에 문제가 있으면 승인할 수 없어요.
- **증명서 확인**: 모든 항목에 '일치'를 체크해야 확인 완료할 수 있어요. 아니면 사유를 골라 재제출을 요청해요.
- **사이드바 배지**: 처리 대기 건수예요. 처리 · 답변하면 바로 줄어요.

## 3. 공통 규칙

- **되돌리기 어려운 동작은 한 번 더 확인해요.** 요청 · 신청 취소, QR 재발급 · 사용 중지, 지도 노출 중지, 회원 탈퇴 등.
- **처리 결과는 화면 위 알림으로 알려 줘요.** 예: "수정 요청(REQ-0143)을 보냈어요." (초록 알림, 닫기 버튼)
- **버튼은 조건이 맞을 때만 켜져요.** 꺼진 이유는 버튼 근처에 글로 적어요.
- **입력 오류는 칸 바로 아래에** 빨간 글자로 보여줘요. 확인된 값은 초록 ✓ 로 보여줘요.
- **불러오는 중 · 실패 · 비어 있음** 상태 문구를 모든 목록에 넣어요.
- **개인정보는 가려서** 보여줘요. 예: 김*희, 010-****-0000. 증명서 열람은 기록이 남아요 (SER-001).
- **팝업**: 배경을 누르거나 Esc 를 누르면 닫혀요. 팝업끼리 이어서 열 수 있어요 (이벤트 상세 → 참여 신청 → 신청 내역).
- **공용 부품을 먼저 써요.** `Button`, `Field`, `Card`, `Modal`, `PageHeader`, `Notice`, `Tag`, `StatusChip`, `JudgmentChip`, `KpiCard`, `Timeline` (`src/components/common`).
